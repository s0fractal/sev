## P1 — the envelope's top-level schema was never derived

Warrant's own verifier enforces the shape outright:

```python
if set(env) != {"body", "sigs"}:
    out("ERR", wid, "envelope must be {body, sigs}")     # impl/warrant.py:1271
```

SEV derived readability from decodability alone. A genuinely pretty-printed
envelope — the same form every real store uses — carrying
`"attacker_extra": 1`, with body and WarrantID untouched and the snapshot
resealed:

```
parse_strict: ['NOT_CANONICAL']   # legitimate for an envelope
snapshot:     []
receipt:      []
projector:    output emitted, record node emitted
```

So SEV projected as evidence a record that Warrant's own verifier rejects.
The attack rides on exactly the form this repository just argued must be
accepted, which is what makes it sharp: widening one door required checking
the next.

**Disposition.** The top-level shape is derived (`set(obj) == {"body",
"sigs"}`) and joined with acknowledgement on the same pattern as a parse
failure:

| Derived | Receipt says | Result |
|---|---|---|
| shape wrong | `MALFORMED_ENVELOPE/ERR` | **valid receipt**; record excluded, never a graph node |
| shape wrong | nothing, or the wrong code | `MALFORMED_ENVELOPE_UNREPORTED` |
| shape right | `MALFORMED_ENVELOPE` claimed | `SPURIOUS_MALFORMED_ENVELOPE` |

The identity-residue rule carries over: a refused envelope MUST have
`computed_wid: null` and `id_sound: false`, else
`UNREADABLE_WITH_IDENTITY_CLAIM`.

Six vectors, all on genuinely pretty-printed bytes: extra member
unacknowledged (refused) and acknowledged (valid, excluded, no record node);
spurious claim over a sound envelope; identity residue; and a missing
`body` or `sigs`.

upstream documentation ambiguity. SEV keeps accepting real pretty-printed
envelopes, and this is one more item for the eventual WRT filing rather than
