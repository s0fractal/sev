## P1 (core) — a missing store meant "everything checked"

`cas` defaulted to `None` on the composed public verdict, while WarrantID
re-derivation, envelope signature/reason completeness and the semantic
reason binding all run only when a store exists. On a fully resealed
countervector — `body.ts 1 → 2`, record digest, descriptor and
`bundle_root` recomputed, receipt keeping the old `claimed_wid`/
`computed_wid`:

```
CAS omitted   []
CAS supplied  ['COMPUTED_WID_MISMATCH']
receipt ok=True errors=0
project(..., cas=None) -> findings [] , output emitted True
```

So absence of the evidence bytes read as a successful verification — the
exact inverse of the receipt core's re-derivability claim — and the MVP
projector emitted a graph on that basis.

**Disposition.** `cas` is now a required argument; `None` yields
`CAS_REQUIRED` and nothing else. Shape-only inspection survives under a
deliberately different name, `validate_structure_only()`, documented so its
clean result cannot be mistaken for verification. The projector inherits the
refusal before any projection.

Vectors: the resealed body caught **with** bytes (`COMPUTED_WID_MISMATCH`),
refused **without** a store (`CAS_REQUIRED`), and reported as unresolvable
with an **empty** store; plus the projector refusing outright.

## P2 (core) — the failure path re-executed hostile code

`repr(exc)` on an attacker-supplied exception is a call into attacker code,
and `bytes(data)` invokes an overridden `__bytes__` on a subclass. Both
escaped as host exceptions. Now: only the exception's class name is used,
and only exact `bytes` / `bytearray` are accepted. Vectors cover an
exception with a hostile `__repr__` and a `bytes` subclass with a hostile
`__bytes__`.
