## P1 — an acknowledgement did not have to name the record it acknowledged

Both acknowledgement branches added in rounds 8 and 10 joined on
`code + severity` only. The locator was never compared, so an issue whose
`at` names `.warrants/blobs/p` successfully "acknowledged" a defect in a
*different* record:

```
validator: []
projector: output emitted
exclusions[]: carries the wrong coordinate as evidence
```

Reproduced on both branches — `RECORD_UNREADABLE` and
`MALFORMED_ENVELOPE`. The receipt validated, the projection emitted, and
the exclusion record — the artifact whose entire job is saying *which*
member was excluded and why — carried a false coordinate.

**Disposition.** One shared join, `_acknowledges(issues, code, path)`,
matching the exact triple `(this source's path, code, ERR)` for both
branches. The docstring states the reason plainly: an issue naming another
member describes that member, and letting it stand in for this one turns
the exclusion record into a false coordinate.

Three permanent vectors: a misdirected `MALFORMED_ENVELOPE`, a misdirected
`RECORD_UNREADABLE`, and — added when mutation showed the severity clause
was not isolated — an acknowledgement with the right code and path at
`WARN`, which does not acknowledge, because an acknowledgement that does not
make the record fatal has acknowledged nothing.
