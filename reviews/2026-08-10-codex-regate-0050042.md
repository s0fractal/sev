## P1 — PROV has one disjoint pair among the roots, not three

The machine modelled `Activity`, `Entity` and `Agent` as three mutually
disjoint kinds and rejected any node closing to more than one. But PROV-O
declares only `prov:Activity owl:disjointWith prov:Entity`; an Agent may
also be an Entity, and PROV-O's own normative `wasAssociatedWith` example
types its agent as `Person`, `Agent` **and** `Entity`. That example was
rejected by the guard:

```
{('disjoint', 'agent+entity', 'urn:derek'),
 ('object', 'wasAssociatedWith', 'urn:derek')}
```

A formal type machine refusing normative PROV is exactly as defective as the
membership list it replaced — in the other direction.

**Disposition.**

- `DISJOINT_PAIRS = (("activity", "entity"),)` — an explicit axiom set, so
  adding a pair is a deliberate act with a citation rather than a side
  effect of counting kinds.
- After the declared pairs are settled, a position asks only whether the
  required kind is **present** (`want in have`), not that it is the only
  one — a legal `Agent ∩ Entity` node satisfies both an Agent and an Entity
  position.
- The `Activity ∩ Entity` vector was sharpened accordingly: with `want in
  have`, that node satisfies the *position* and is caught by the
  *disjointness* finding, which is the sharper and more accurate outcome.

Vectors: PROV-O's Derek example accepted verbatim, and the same agent
accepted in an Entity position.
