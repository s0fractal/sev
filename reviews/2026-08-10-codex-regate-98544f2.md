## P1 — the bidirectional guard was not total over its own type table

Activities were recognised by a two-element tuple,
`("sigma#CheckRun", "wrt#Filing")`. So the guard did not see an **explicit**
`rdf:type prov:Activity`, nor the profile's own `sev:VerificationActivity`,
and let either stand in a `prov:used` Entity position — although PROV makes
Activity and Entity disjoint. Two further branches of the same defect: the
signature table declared an Agent range that no code path ever evaluated,
and object checks ran only for terms starting with `<`, so **literals passed
every PROV object-property position**.

The flagship graph was not wrong — it passed. But a load-bearing guard
covering less than it claims cannot be evidence for a freeze.

**Disposition.** The guard now:

- classifies through a **closed registry** carrying the PROV base classes
  (`Activity`, `Entity`, `Agent`, plus `Bundle`/`Plan`) and every subclass
  the profile declares, so disjointness is decided on types rather than on a
  hard-coded pair;
- evaluates the **agent** position, and adds `prov:wasAttributedTo`
  (Entity → Agent);
- **rejects literals** in any PROV object-property position;
- parses N-Quads **structurally** (IRI or literal terms) instead of
  splitting on spaces;
- keeps untyped nodes as Entities, which is what the profile says they are.

Six permanent countervectors, including the reviewer's three verbatim:
explicit `prov:Activity` in an Entity position, `sev:VerificationActivity`
likewise, a Warrant record in an Agent position, a literal in an Agent
position, a literal in an Entity position, and a spaced literal parsing as
one term.
